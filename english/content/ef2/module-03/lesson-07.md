## Role-Play

### Scenario: Anna, the marketing manager, attends a meeting with David, the IT manager.

### David explains a new website security update

**Anna:** Hi David, I heard we’re making some security updates to the website. Can you tell me what’s changing?

**David:** Absolutely. In simple terms, we’re making the website safer for everyone who visits.

**Anna:** That sounds important. What exactly are you doing?

**David:** We’re installing a digital “lock” called an SSL certificate. To put it another way, this means any information people enter on our website will be private and protected from hackers.

**Anna:** Oh, I see! And what about the other updates you mentioned?

**David:** Good question. We’re also adding “two-factor authentication.” In layman’s terms, it’s like needing two keys to open a door. This makes it much harder for anyone to break into our site without permission.

**Anna:** That makes sense. Will any of this affect my work on the website?

<!-- Source: F2_M03_L07.pdf, page 2 -->

**David:** Not really. The updates will run in the background. But you might notice a small padlock icon in the web address bar, that shows the site is secure. If you have any trouble logging in, just let us know. Does that make sense?

**Anna:** Yes, thank you for explaining! That was really clear.

### Role-play analysis

1. Which phrases did David use to help explain technical ideas simply to Anna?

2. How did David check if Anna understood his explanations?

3. How did David turn technical terms (like “SSL certificate” or “two-factor authentication”) into clear, everyday language?

4. What could happen if David did not take time to explain these updates clearly?

5. Do you think it is always necessary to avoid all technical terms when speaking to non-technical people? Why or why not?

### Example

**Original Brief:** “We need to optimize the user interface by enhancing the responsiveness and ensuring cross-platform compatibility before deployment.”

**B:** Can you please help me explaining our brief today?

**A:** To put it simply, we want to make the app faster and easier to use before we make it available.

**B:** Oh, I see. But what does “cross-platform compatibility” mean?

**A:** It means you can use the app on different devices. Would you like me to explain more?

### Project Briefs

1. “Our team will migrate the database to a cloud-based infrastructure and implement data encryption to comply with security protocols.”

2. “The application will undergo regression testing to identify potential issues caused by recent code changes.”

3. “The mobile version will support push notifications and synchronize in real time with the desktop app.”

**Case Study 1:** Setting Up Cloud Storage

Two IT managers are briefing the software development team about the transition to new cloud storage.

| Team Manager A | Team Manager B |
| --- | --- |
| “We’re migrating all project directories to<br>our new Azure cloud infrastructure. Please<br>begin transitioning your team’s source code<br>repositories and documents to OneDrive<br>using authenticated single sign-on.<br>Remember to enable multi-factor<br>authentication and tag all shared folders<br>according to our standard protocol.” | “From now on, please save your<br>work in an online folder instead of<br>your own computer. It’s safer and<br>means you can work from<br>anywhere.” |

### Analysis Questions

- Which briefing would a technical team prefer? Why?

- When is it important to use precise technical terms?

- What could go wrong with only a simple explanation in this context?

**Case Study 2:** Explaining the Firewall Upgrade

Three IT managers are presenting to a team with IT, HR, and sales representatives about the security change.

| Team<br>Manager A | “Our new stateful inspection firewall is configured to monitor all<br>incoming and outgoing network packets. Please report any<br>blocked connections with detailed info on your port and protocol.” |
| --- | --- |
| Team<br>Manager B | “We upgraded our security guard for the internet. If you see any<br>strange warnings, please tell us.” |
| Team<br>Manager C | “We recently upgraded our perimeter firewall to include stateful<br>inspection, which means it now checks every signal in and out for<br>signs of attack. In simple terms, the firewall is like a guard at the<br>company gate, helping keep out hackers and unsafe software. If<br>you ever get a warning about blocked access, let us know—it’s<br>usually the firewall doing its job to keep everyone safe.” |

### Analysis Questions

- Which manager’s brief is the most effective in this context?

- Who benefits from technical detail? Who benefits from the easier explanation?

- Is anything missing from one style alone?

**Case Study 3:** Reporting a Bug

The customer service team regularly uses a new software platform. Some staff have noticed problems, but they’re unsure how to report these to IT. Two IT managers need to explain the procedure for reporting bugs.

| Team Manager A | Team Manager B |
| --- | --- |
| “If you encounter any system<br>anomalies or error messages, please<br>log the incident in the bug tracking<br>system, specifying the steps to<br>reproduce the issue and attaching<br>relevant logs or screenshots.” | “If something goes wrong with your<br>program—for example, if you see a<br>strange message or it doesn’t work as<br>expected—please send us an email<br>describing exactly what happened. If<br>you can, include a picture or tell us<br>what you were doing before the<br>problem.” |

### Analysis Questions

- Which briefing is easier to understand for the team in this situation? Why?

- What problems might happen if you only use the technical briefing?

- Is there any information missing from the simpler briefing? How could it be improved?

### Discussion

1. In what type of situation is it better to use technical terms? When should you use simple language? Give examples.

2. In your opinion, what is the best way to explain this IT information to a non-technical team?

3. When you are listening to a technical explanation, what can you do if you don’t understand? What useful questions can you ask?

4. What strategies can you use in the future to communicate technical ideas more clearly to people with different backgrounds?
